## 2. 方向

### D1. 重機旅遊規劃顧問（Moto Touring Copilot）— 建議

**情境：** 「週六想騎南橫，天氣和路況怎樣？幾點出發才能在天黑前回來？油夠不夠？」

| 面向 | 內容 |
| --- | --- |
| 使用者 | 在台灣騎重機長途旅遊的騎士（起點就是你自己） |
| 資料 | 自己的歷史 GPX（**實際騎乘時間就是正確答案**）；氣象署預報；交通部 TDX 路況與道路阻斷事件；道路與地形（OpenStreetMap、內政部數值地形）；加油站開放資料 |
| 分析 | 個人化騎乘速度模型：依彎道曲率、坡度、道路等級、時段預測每段路要騎多久；多元迴歸（L6）當 baseline，再和梯度提升樹比較；天氣與路況風險評分；油量與加油站距離檢查 |
| 評估 | 用沒參與訓練的自己的行程，比較預測時間 vs 實際時間，並和一般導航的時間估計比較 |
| Agent | 很適合多 Agent 分工：規劃 Agent 加上天氣、路況、配速分析等專責 Agent |
| L3 延伸 | 騎乘中手機定位經 MQTT 回傳，即時更新抵達時間，遇到天氣或道路阻斷時用耳機語音提醒（不需要看手機） |
| 既有方案 | 重機路線 App（例如 Calimoto、Kurviger、REVER）能規劃彎道多的路線、記錄騎乘；導航 App 有一般的時間估計；**切入點**：個人化配速、台灣天氣與道路阻斷、可解釋的風險評估 |

### D2. 騎乘回顧與安全教練（Ride Analyst）

用 GPX、Insta360 的動態感測資料、行車記錄器 GPS，分析急煞、過彎速度、傾角等騎乘行為。

- 優點：資料都在手上，題目有個人特色。
- 缺點：「安全」沒有可驗證的正確答案；X5 資料格式和時間對齊都還不確定。

### D3. 旅程影片 Agent

從 360 度影片和行程資料自動挑精華片段，搭配 ComfyUI 生成封面。

- 優點：有趣，用得到 ComfyUI 和 Insta360。
- 缺點：資料分析和領域知識的成分低，不符合老師「不要只做生成」的要求；比較適合當 D1 的輸出加分項。

## 3. D1 的資料量與取得方式（2026-10-25）

- **GPX：** BMW App 裡有 279 趟歷史行程，重新連線後還會再增加一些。
- **匯出：** 官方說明只有逐趟匯出（行程 → 右上選單 → Export GPX），沒找到批次匯出功能。先匯出 20–30 趟有代表性的行程做驗證，夠了再補。
- **歷史天氣：** 訓練模型需要騎乘當下的天氣。官方「全測站逐時氣象資料」在政府開放資料平台，大量下載要申請氣象資料開放平臺會員；中興大學有一個非官方的[氣象觀測資料下載器](https://mycolab.pp.nchu.edu.tw/historical_weather/)，可以依測站下載 CODiS 歷史逐時資料。
- **隱私：** GPX 含住家等位置，原始檔不要放進 repo；要公開的資料先把每趟頭尾裁掉（VED 也是這樣處理）。

### D1 驗證（spike）計畫

1. 匯出 20–30 趟行程，涵蓋山路、市區、不同季節，放在 repo 以外的資料夾。
2. 清理車速雜訊，把每趟切成固定長度的路段（例如 500 m），算每段的彎道曲率、坡度、時段，對接最近測站的天氣。
3. 目標是每段路花的時間；依行程分組做交叉驗證，比較平均速度 baseline、多元迴歸、梯度提升樹。
4. 通過標準：個人化模型對整趟騎乘時間的誤差明顯小於 baseline，且彎道、坡度的係數方向合理。
