# 期末專題方向：重機旅遊規劃顧問（Moto Touring Copilot）

> 2026-10-25 定案，給組員看的簡要說明。詳細決策見 `architecture-scope.md`。

## 專案說明

**一句話：** 一位懂台灣山路、天氣和你騎乘習慣的 AI 規劃顧問。它用騎士自己的歷史行程（GPX）學出個人配速，再結合氣象署天氣、公路路況、地形和加油站資料，由多個 Agent 分工規劃、互相驗證，回答「幾點出發才能天黑前回家、哪裡加油、哪段路有風險」。

**為什麼做這個：**

- 台灣 2025 年道路死亡 2,858 人，只比前一年少 3.1%；交通部指出機車族群死亡比例偏高、自摔自撞事故惡化。
- 山區道路常因颱風、地震預防性封閉，午後山區容易下雨。
- 一般導航只有通用的預估時間，不知道你騎多快，也不會把天氣、封路、加油站、日落時間放在一起看。
- 研究顯示 LLM 自己做不好時間和距離的計算，需要外部工具計算和驗證；這正是這個 Agent 的設計重點。

**資料：**

- 自己的 279 趟 BMW 重機行程 GPX（實際騎乘時間就是模型的正確答案）。
- 氣象署預報與歷史觀測、交通部 TDX 省道路況、內政部地形、OpenStreetMap 路網、中油與台糖加油站。
- 知識庫：氣象署警特報說明、公路局行車資訊、騎乘安全資料、BMW 車系規格、相關論文。

**實作範圍：** 承諾做到 L2（知識庫 + 多步推理的 Agent + 真正的資料分析）；L3（騎乘中手機定位即時回傳、語音提醒）列為延伸。

## 對應老師的 ①–⑩

| 項目 | 我們的做法 |
| --- | --- |
| ① 使用者與情境 | 在台灣騎重機旅遊的騎士。情境：規劃行程、出發前檢查天氣與路況、油量與加油點 |
| ② 互動介面 | Web 對話介面，用地名描述行程，可匯入 GPX |
| ③ 領域代理人 | 多 Agent 分工：規劃、配速分析、天氣、路況與補給、驗證；驗證不通過就重新規劃；記住騎士偏好 |
| ④ 六大能力 | TALK 多輪對話、KNOW 知識庫附出處、SENSE 自己的 GPX 加官方資料、ANALYZE 配速預測、THINK 多 Agent 與驗證、SHOW 地圖與行程計畫 |
| ⑤ 資料與工具 | 自己的 GPX、氣象署、TDX、地形、路網、加油站、知識庫；Python 分析工具與 Google Maps Platform |
| ⑥ 分析引擎 | 個人配速模型：多元迴歸 → 梯度提升樹，附預測區間；和平均速度、Google Maps 預估時間比較；天氣與路況風險規則 |
| ⑦ 輸出呈現 | 對話 + Google Maps 行程儀表板（路段依時間和風險上色、加油站、日落時間）+ 可下載的行程計畫 |
| ⑧ 領域 | 重機旅遊規劃 |
| ⑨ 難度 | L2 實作，L3 延伸 |
| ⑩ 成果證據 | 和 baseline 比較、2–3 個完整案例、消融實驗（只用 LLM vs 完整 Agent） |
